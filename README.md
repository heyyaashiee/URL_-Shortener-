# URL Shortener — Backend (Steps 1–3: Setup, Core Logic & Auth)

Step 1 built the project structure and database. Step 2 added base62
short-code generation and the core `/shorten` + redirect endpoints. Step 3
adds JWT authentication — `/shorten` and `/my-links` now require a logged-in
user, and every URL is tied to its owner.

## Project structure

```
backend/
├── app/
│   ├── __init__.py
│   ├── database.py       # DB connection, session factory
│   ├── models.py         # User, URL, Click tables
│   ├── schemas.py        # Pydantic request/response models
│   ├── shortener.py      # base62 short-code generation + collision handling
│   ├── auth.py            # password hashing, JWT creation/verification
│   ├── routers/
│   │   ├── __init__.py
│   │   ├── auth.py       # POST /auth/signup, POST /auth/login
│   │   └── urls.py       # POST /shorten, GET /my-links, GET /{short_code}
│   └── main.py           # FastAPI app + health check
├── requirements.txt
└── .env.example
```

## Setup

1. **Create a virtual environment**
   ```bash
   python -m venv venv
   source venv/bin/activate   # On Windows: venv\Scripts\activate
   ```

2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

3. **Set up PostgreSQL**
   - Install PostgreSQL locally, or use a free hosted instance (e.g. Railway, Supabase, Neon).
   - Create a database, e.g. `url_shortener`.

4. **Configure environment variables**
   ```bash
   cp .env.example .env
   ```
   Then edit `.env` and set your real `DATABASE_URL` and a strong random
   `JWT_SECRET_KEY` (used to sign login tokens — don't use the example value).

5. **Run the server**
   ```bash
   uvicorn app.main:app --reload
   ```

6. **Verify it works**
   - Visit `http://localhost:8000/` → should return a welcome message
   - Visit `http://localhost:8000/health` → should return `{"status": "ok", "database": "connected"}`
   - Visit `http://localhost:8000/docs` → interactive Swagger UI (auto-generated by FastAPI)

   On first run, `Base.metadata.create_all()` will automatically create the
   `users`, `urls`, and `clicks` tables in your database.

## Schema overview

| Table  | Purpose                                                        |
|--------|-----------------------------------------------------------------|
| users  | Registered users who create and manage short links             |
| urls   | Maps a `short_code` to the `original_url`, linked to an owner  |
| clicks | One row per redirect — powers the analytics dashboard later     |

## Trying it out

With the server running (`uvicorn app.main:app --reload`):

**1. Sign up**
```bash
curl -X POST http://localhost:8000/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "yourpassword"}'
```

**2. Log in** (note: this endpoint takes form data, not JSON — it follows
the OAuth2 spec so it works with Swagger UI's "Authorize" button)
```bash
curl -X POST http://localhost:8000/auth/login \
  -d "username=you@example.com&password=yourpassword"
```
Response includes an `access_token` — copy it for the next step.

**3. Shorten a URL** (now requires the token)
```bash
curl -X POST http://localhost:8000/shorten \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <paste_your_token_here>" \
  -d '{"original_url": "https://www.example.com/some/very/long/path"}'
```

**4. List your links**
```bash
curl http://localhost:8000/my-links \
  -H "Authorization: Bearer <paste_your_token_here>"
```

**5. Use the short link** — no auth needed, redirects (HTTP 307) to the original:
```bash
curl -i http://localhost:8000/aZ9kLp
```

Or just open `http://localhost:8000/docs`, click "Authorize", log in, and
try every endpoint interactively.

### How short codes are generated
`app/shortener.py` picks a random 6-character base62 string
(`a-zA-Z0-9`, ~56.8 billion combinations) and checks the database to make
sure it isn't already taken, retrying a few times on the rare chance of a
collision. Worth knowing this approach vs. encoding an auto-increment ID —
both come up as system-design interview talking points.

### How auth works
- Passwords are hashed with bcrypt (`app/auth.py`) — never stored in plain text.
- Login issues a JWT containing the user's id (`sub` claim) and an expiry,
  signed with `JWT_SECRET_KEY`.
- Protected routes use the `get_current_user` dependency, which decodes the
  `Authorization: Bearer <token>` header and raises 401 if it's missing,
  expired, tampered with, or belongs to a deleted user.

### ⚠️ Two bugs I hit while building this (worth knowing)
1. **Route ordering**: `GET /{short_code}` is a catch-all path. It must be
   registered *after* `/`, `/health`, `/auth/*`, and `/my-links` in
   `main.py`/`urls.py` — otherwise it swallows those requests too, since
   FastAPI/Starlette matches routes in registration order.
2. **passlib + bcrypt version mismatch**: `bcrypt` 5.x removed an internal
   attribute that `passlib` 1.7.4 depends on, causing hashing to fail. Fixed
   by pinning `bcrypt==4.0.1` in `requirements.txt`. A good reminder to pin
   versions for anything security-related.
